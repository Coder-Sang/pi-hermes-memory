## 目标与已确认方案

当前记忆创建、部分更新和失败恢复直接调用 `fs.link()`，文件系统不支持硬链接时会导致写入或恢复失败。旧数据库迁移中也存在同样的依赖。

采用**优先使用硬链接，失败时自动降级为排他创建并复制**的方案，同时覆盖记忆读写、恢复和旧数据库迁移。

完成标准：在模拟硬链接不可用的环境中，记忆创建、更新、恢复以及数据库迁移可以完成；目标已存在时仍按冲突处理，真实 I/O 错误不误报成功，失败时保留可用的恢复数据。

## 默认与限制

- 自动按实际操作错误降级，不增加用户配置，不缓存全局文件系统能力；现有工具参数和公开调用接口保持兼容。
- 降级复制期间，外部读取可能看到部分内容，进程中断也可能留下未完成文件；该路径不承诺硬链接发布的原子可见性。
- 假设目标文件系统支持排他创建、现有重命名和 SQLite 锁。部分网络文件系统可能不可靠地支持排他创建，需在实际挂载环境验收。
- 本任务不包含发布、版本升级或改变记忆数据格式。

参考：[Node.js 文件打开标志说明](https://nodejs.org/api/fs.html#file-system-flags)。`wx` 在目标路径已存在时失败；官方文档同时说明部分网络文件系统可能不支持排他标志的预期语义。
